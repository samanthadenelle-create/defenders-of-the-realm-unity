**Status:** Source / asset-builder files written. The integrator runs the Unity

## Enemy layer

**`Enemy` = user-layer index 8.** `TagManager.asset` slot 8 was the first free
user slot (0 Default, 1 TransparentFX, 2 Ignore Raycast, 3 free, 4 Water, 5 UI,
6 free, 7 free, **8 Enemy**). The builder:

- puts the generated enemy prefab (and all its child renderers) on layer 8;
- sets `HeroAbilities._enemyMask`, `PetDeployer._enemyMask` to `1 << 8`
  (`PetDeployer` forwards its mask to each spawned `Pet`, so `Pet._enemyMask`
  is covered too);
- leaves `BuildMenu._groundMask` at `1 << 0` (Default) so the placement raycast
  hits the ground tiles and not buildings.

## NavMesh bake

Done **inside `BuildVillage()`** as a clearly-named step it calls
(`BakeVillageNavMesh`), after all geometry is placed.

- **API:** the legacy `UnityEditor.AI.NavMeshBuilder` — the manifest carries
  `com.unity.modules.ai` 1.0.0, **not** `com.unity.ai.navigation`
  (NavMeshSurface). `ClearAllNavMeshes()` then `BuildNavMesh()` — a synchronous
  bake of the active (Village) scene, idempotent on a re-run.
- **Navigation-static marking:** every renderer under `Ground`, `Roads`,
  `Approaches`, `Walls`, `Gates`, `Buildings` is flagged
  `StaticEditorFlags.NavigationStatic` via `GameObjectUtility`. Ground / roads /
  approaches are the walkable floor; walls / gates / buildings are obstacles the
  agents path around.
- **Agent fit:** the bake uses the project's default NavMesh agent settings
  (Window > AI > Navigation > Agents — Unity default Humanoid: radius 0.5,
  height 2.0). The enemy `NavMeshAgent` is tuned to radius 0.4 / height 2.0,
  which fits inside the bake agent, so the baked mesh is valid for it.

## IDamageableStructure adapters

`Enemy.cs` declares `IDamageableStructure { bool IsAlive; void ApplyContactDamage(float); }`.
The three structures now implement it as thin adapters onto their existing
damage APIs — no existing behaviour changed:

- **Building** — `ApplyContactDamage` → `ApplyDamage`; `IsAlive` = `_hp > 0`.
- **Gate** — `ApplyContactDamage` → `TakeDamage` (already drives the shader
  collapse + blocker toggle); `IsAlive` = `_hp > 0`. Note: the field stops
  *blocking* at the 25% collapse threshold (`IsForceFieldUp`) but stays
  *attackable* (`IsAlive`) down to 0 HP, so an enemy keeps chipping at a
  collapsing gate.
- **WallSegment** — the Week-3 skeleton had `_damage` (0–100, accumulating) but
  no setter, so `ApplyContactDamage` was authored to accumulate onto it (clamped
  0–100), with a matching `Repair`, plus `DamageChanged` / `Collapsed` events.
  `IsAlive` = `_damage < 100`.
