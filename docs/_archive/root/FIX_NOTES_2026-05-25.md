## SOLVED — re-apply cleanly, verify each

### A. Village build crash — `level3 corrupted / [Position out of bounds]`
- Native crash (UnityPlayer stack) loading Village in a *clean* build.
- Ruled out: static batching (already OFF in ProjectSettings), D3D12 upload buffer (forcing D3D11 alone did NOT fix it), GUID mismatch (all resolve), stale exe-stub (clean builds).
- **Root cause:** Village scene serialization sits on a fragile edge because of ~500 MB of raw un-decimated Tripo/pet meshes referenced/baked in. Intermittent — re-bakes flip between a good and a corrupt `level3`.
- **Fix that worked:** cut the mesh budget **and** do a fresh re-bake of Village → clean `level3`.
  - Cleanest option (owner-approved): swap the giant Tripo village buildings for **lightweight KayKit stock** buildings — no decimation, no UV breakage, no crash.
  - If decimating instead: **gentle** (~10–15 MB, NOT 2–5 MB) to keep UVs; **overwrite the .fbx in place, keep the .meta** (preserves GUID). Aggressive decimation scrambles UVs → wrong colors.
- Offending meshes: Cathedral 84 MB (REMOVED — replaced by tree), PetHome 54, LumberMill 52, Forge/Farm 29, Portal 27, pets ice-wolf/flame-pup/aether-sprite 90–100 each, pet-aether-twilight 91.
