Component anatomy specs for CLI to build against

Filter chips

One horizontally-scrollable row of pill chips under the medallion — never five square plates dividing the body width.

  • Full labels: All · Story · Daily · Gear · Endgame — no mid-word clip.
  • Selected = gilt fill + underline marker + leading ◆ glyph (shape, not colour alone).
  • Row scrolls horizontally if a 6th filter is ever added; each chip ≥112 ref-px tap.

List card (the row)

A card is a select-target only — the button leaves the row entirely.

  • Line 1: quest title (bold parchment) + a state pip — New / Tracked.
  • Line 2: one-line objective hook, dim, ellipsised at one line.
  • Selected card = 3px gilt left-border + warmer fill. Whole card is tappable.
  • List lives in a scroll well (MakeScrollZone) — rows never stack/overlap.

Detail pane

Obsidian-dark (not the tan slab), always bound to a selection — first available rumor auto-selected on open and on tab change.

  • Tag row (type · level · region) · gilt title · full tale.
  • Objectives list + Rewards row (XP / crystals / items).
  • Primary CTA full word: Accept (→ Track when active → Turn in when done), ≥112px, plus a secondary action.

Empty states

Quiet, not structural — an empty section must never dominate the board.

  • In Progress empty → a single dim line (“nothing underway”), no section slab.
  • No rumors under a filter → one dim line inside the list, not a half panel.
  • Nothing selected → detail shows a short prompt (only when the list is truly empty); otherwise a rumor is always auto-selected, so the pane is never blank.

The one load-bearing decision

Accept leaves the list row and lives in the detail pane. That single move fixes the ACC… truncation (the CTA finally has width), un-crushes the list (rows become clean title + hook), and gives the empty right pane a permanent job (it always shows the selected rumor's tale + the button you press). Everything else — chips, collapsing empty states, corner Close — follows from making the board a real master–detail.
