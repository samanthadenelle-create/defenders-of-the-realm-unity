## 3. What the product actually IS (your methodology, made teachable)
This is the content — and it already exists, lived, in this repo. The teaching is just structuring what you do:

1. **The canon doc** (your `CLAUDE.md`) — how a single "rules the agent reads first, every time" doc stops
   agents from inventing files/APIs and drifting. The single highest-leverage guardrail.
2. **The work-order pipeline** — turning fuzzy intent into a spec the agent can't misread (files to touch,
   acceptance criteria, what NOT to touch). How you keep scope from ballooning.
3. **The gate** — never trust "it's done"; a cheap automated check (compile/brace/regression) the work must
   pass before it counts. How you stop "confidently wrong."
4. **Instrument-first / don't-guess** — make the system report WHY it's failing (captured data) instead of
   letting the agent theorize. The single biggest credit/time saver.
5. **Orchestrate, don't solo** — you as the orchestrator: delegate deep work to agents, keep your hands on the
   gates + the through-line. Parallel agents on disjoint work. (This is pure PM.)
6. **Bones-first + data-structure thinking** — get a working skeleton + structure the problem as data before
   polishing; keep the system legible.
7. **The felt-test / break-capture loop** — how the human stays the judge of *feel* while the machine catches
   the breaks (so you're never the bug detector).

Every one of these has a **war story** in this project — the night the agents went off the rails vs the night
the canon caught it; the pink-floor guessed-at-for-3-cycles vs instrumented-and-found-in-one; the bone-mapping
"data structure" reframe. The stories ARE the teaching — and they're yours.
