Build UI Redesign — three directions

Driven by tester feedback: "couldn't understand it... too hard... buttons everywhere." Benchmark: Clash of Clans (owner tie-breaker rule).
Current screen carries ~10 competing elements — X Done, "Placing:" hint pill, Rotate Left, Rotate Right, PLACE, Cancel (all full-word buttons), a 4-way D-pad, and the resource strip (BuildHudController.cs). CoC ships the same job with 3 contextual controls that appear only when needed, next to the thing being placed. Every direction below follows that principle: controls live on the object, not on the screen.

Direction A — "CoC Classic": contextual chips only 5 elements on screen

No bars, no mode chrome. The ghost IS the interface: drag it with a finger; ✓ ⟳ ✗ chips float beside it. Green/red footprint = valid/invalid (plus the chips gray out — never color alone). Shop is a pull-up tab, closed by default.

Direction B — "Carousel + minimize" (prior owner ruling, refined) 6 elements on screen

Large card carousel to PICK (art + cost + affordability). On select it minimizes to an edge tab, freeing the whole screen. Placement then works exactly like Direction A (chips on the ghost). Tiny D-pad toggle in the corner for pixel-nudge on small pieces — off by default.

Direction C — "Zen two-phase": full-screen shop → gesture-only field 4 elements on screen

Phase 1: a proper full-screen SHOP (grid, categories, counts — like CoC's shop). Phase 2: the field is completely clean; ONE bottom pill holds cancel / name+cost / rotate / confirm. Drag to move, twist two fingers to rotate.

Recommendation: Direction B, borrowing C's shop grid later. B is the CoC placement grammar (contextual chips on the ghost, field freed by minimize-on-select) plus the guided pick that new players need, and it matches the build-HUD ruling already on record — with the smallest refactor because LeanTouchBuildDriver (drag/pinch) and the card palette already exist. A is the fallback if the carousel feels heavy in playtest; C is the end-state to grow toward once gestures are proven discoverable.
All directions keep the binding constraints: MinTouchPx 112 on every control, state carried by text/shape (never color alone — red/green colorblind rule), code-built uGUI (no UXML), ASCII strings in-game (emoji here are mockup-only stand-ins for the real resource icons).
